# 91APP Payments 後台功能參考（SoundLite 專案視角）

> 來源：《91APP Payments 後台使用手冊》V1.8 / 2026-06（125 頁）全本萃取。
> 建立：2026-07-19。用途：補齊 API 文件沒寫、但**營運/財務/客服/對帳**會用到的後台知識。
> 搭配文件：`PAYMENT_91APP_MIGRATION_ASSESSMENT.md`（技術評估）、`PAYMENT_91APP_VENDOR_QUESTIONS.md`（待確認清單）。

## 0. 一句話重點

91APP 後台與藍新最大的差異在**金流資金模型**：**不是「T+N 自動撥款進你銀行戶」，而是「款項先進 91APP 平台虛擬錢包 → 商店主動（或設定自動）提領 → 2–3 工作天匯入銀行戶」的兩段式提領制**。對帳、退款、現金流、客服流程全都圍繞這個模型改變。**且無對帳 API——對帳靠後台「帳務明細查詢」報表匯出。**

---

## 1. 後台總覽 / 帳號安全

- 手冊版本 **V1.8 / 2026-06**；後台網址需簽約後向業務索取（手冊僅標「後台網址請加入最愛」，未印出 URL）。
- **登入**：統一編號/身分證號 + 帳號 + 密碼（p.5）。密碼 12–20 字元、含大小寫 + ≥1 數字（p.4/p.8）。
- **強制 2FA**：Google Authenticator，每次登入輸 6 碼（p.9）。→ 比藍新多一層強制 MFA，營運帳號安全性較高。
- **RBAC 群組權限**（p.11–14）：系統預設「最高管理者」+ 自訂群組；權限三態 **隱藏 / 可查看 / 可操作**；可綁「負責商店」做資料隔離（multi-store 架構）。
  - **「退款」「取消授權」「作廢」是可獨立授權的細分權限**（p.12）——客服退款權限可與其他權限分離，符合最小權限原則。
  - 多次密碼錯誤會鎖定帳號，需最高管理者解鎖（p.13）。
- 後台八大模組（p.2）：`1 帳號相關 · 2 設定(黑名單/支付方式管理) · 3 交易 · 4 帳務 · 5 收款工具 · 6 首頁資訊 · 7 常見問題 · 8 更新說明`。

## 2. 💰 金流資金模型（與藍新最大差異，務必先懂）

### 2.1 撥款鏈（p.44, p.59–60, p.123）
```
消費者付款(訂單日/交易產生日)
  → 系統自動送交請款(結帳日/帳務產生日，B 通常為次日)
  → D+N 天撥款至「91APP Payments 虛擬帳戶」(帳務結算日；D=請款成功日)
  → 商店發動「提領」(手動或自動)
  → 2–3 工作天匯入指定金融帳戶(實際入款日；例假日順延)
```

### 2.2 三個關鍵日（p.65，對帳核心語彙）
| 日期 | 定義 |
|---|---|
| **交易產生日** | 消費者訂單付款成功日（訂單日） |
| **帳務產生日** | 請款成功日（結帳日） |
| **帳務結算日** | 91APP 代收撥款日（款項進虛擬錢包） |

### 2.3 虛擬錢包帳戶概念（p.61–62）
- 每個收款帳戶（例：`92992057805622`）有四個餘額：**可使用總額 / 保留款總額 / 帳戶總額 / 待撥款總額**。
- 錢**不會自動進銀行戶**——停在虛擬錢包，靠「提領」出金。

### 2.4 提領（withdrawal，p.69–71）
- **手動提領**：需 2–3 工作天入帳；**每月 10 次免費**，超過收匯款手續費；提領失敗不退手續費。
- **自動提領** 4 種：每日 / 每週(可複選星期) / 每月(可複選日期) / 達餘額門檻。變更自動提領設定**須洽客服**。
- **可提領金額 ≤ 可使用總額**：退款處理中的金額、商店設定的「提領保留額度」都會壓低可提領數。

### 2.5 對 SoundLite 的意涵
- **現金流變慢且需主動管理**：訂閱收入不會自動到帳，需設自動提領 + 保留一定餘額供退款。財務排程要重新設計。
- **不是「收款即到帳」**：月結報表與實際銀行入帳有時間差（撥款日 ≠ 入款日），會計對帳要用 91APP 的帳務日，不是銀行對帳單日期。

## 3. 🧾 對帳 / 結算（無對帳 API，靠後台報表）

> API 端無對帳端點（已於技術評估確認）。對帳唯一資料源是**後台報表匯出**。

### 3.1 主報表：帳務明細查詢（p.64, p.77；路徑 `帳務 > 帳務明細查詢`）
- 逐筆交易對應帳務；日期可切「帳務產生日 / 帳務結算日 / 交易產生日」。
- **僅能查到載入前一日（T-1）的帳務**——當日資料次日才齊。
- 欄位：`帳務處理編號`、`帳務來源編號(=交易編號)`、`商店訂單編號`、`撥款金額`、`費用金額`、`帳務項目`、`帳務來源(請款/退款)`、`類型(撥款/費用)`、三個日期、`帳務狀態`。
- 彙總列：總筆數、撥款總金額、費用總金額、**帳務淨額**。
- 右上「匯出資料」。

### 3.2 對帳系統改版（重要，對接對帳程式必看）
- 舊「撥款查詢」已於 **2024/12/25 關閉**，功能併入「帳務明細查詢」（p.122–124）。
- **撥款金額與手續費自 2025/01/06 起拆兩列顯示**（p.117–119）：
  - `AP` 前綴帳務處理編號 = **撥款**存入（如 +NT$100）
  - `DS` 前綴帳務處理編號 = **手續費**支出（如 −NT$2）
  - 對帳程式須把同一 `帳務來源編號`(交易) 的 AP/DS 兩列合併還原淨額。
- 舊→新欄位對照（p.124）：預計撥款日→帳務結算日、請退款成功日→帳務產生日、撥款狀態→帳務狀態（待撥款→待結算 / 撥款成功→已結算）、手續費/費率→費用金額（移除費率）、交易編號→帳務來源編號。

### 3.3 兩個對帳鍵值（p.103）
- **帳務處理編號**：款項每次進出的唯一識別（撥款/提領/手續費各一筆）。
- **帳務來源編號** = 91APP Payments 交易編號（= API 的 `tradeId`）。

### 3.4 匯出機制（p.52–53）
- 交易查詢/帳務各報表右上「匯出資料」→ 設**加密密碼** → 建批次作業 → 完成後下載 **zip**（用該密碼解壓）。
- **zip 僅保存 3 天**，逾期需重新產生。→ 若要自動對帳，需排程定期下載歸檔（無 API，得走後台或另問是否有 SFTP/報表 API）。

### 3.5 費用發票（p.79–80）
- 金流手續費**後收**；每月 **3 號**寄「電子發票開立通知」到帳務聯絡人信箱，於「費用發票查詢」下載。
- **系統僅存 1 年發票**，需定期自行下載保存。

### 3.6 提領對帳作業（8 步，p.72–78）
提領入帳金額核對公式（p.76）：
```
提領入帳金額 = 實際代收撥款總額
             + 已歸還的退款保留款總額
             − 帳期內的退款保留款總額
```
帳差常見兩因：(1) 商店設了「保留固定金額」；(2) 提領當日 01:30–02:00 有退款進保留款。

## 4. 退款操作（後台手動，受額度限制）

- **路徑**：交易 > 交易查詢 > 該筆「退款」；退款查詢可看單筆多筆退款紀錄（p.49, p.51）。
- **前置**：需「請款成功（已請款）」才能退款；未請款的交易走「取消授權(void)」而非退款（p.45, p.19）。
- **時限**：授權成功後 **180 天內**可後台退款，逾期洽客服（p.101）。
- **部分退款**：信用卡一次付清 / Apple Pay / Google Pay / LINE Pay 支援，**單筆可多次部分退款**至退完全額（p.20, p.51, p.102）。**分期付款僅接受全額退款**（p.102）。
- **退款到帳**：手冊通知信寫 **7–10 工作天**退回原付款方式（p.20）。
- **退款額度限制（關鍵營運陷阱）**：每帳戶有「退款額度」，**額度為 0 時該商店信用卡/Apple Pay 交易無法退款**，需隔日再申請或洽客服提升（p.56）。
  - 退款額度公式（p.102）：`待結算帳務金額 + 可使用總額 − 退款處理中金額`。
  - 退款款項會進**保留款**、佔用可用總額直到退款撥款完成（p.61）。
- **取消退款**：狀態為「退款已請求」時可取消（p.51, p.116）。
- **單筆金額上限**（p.102）：信用卡 NT$199,999、ATM NT$49,999、超商 NT$20,000。

## 5. 請款（capture）—— auth+capture 兩階段模型

- 91APP 是**授權/請款兩階段**（auth then capture）模型，與訂閱制「先授權後請款」相容（p.19）。
- **自動 vs 手動請款皆支援，但切換須洽客服**（p.101）——後台不能自助切換。訂閱制通常要**自動請款**，導入時要先談定。
- **請款時限**：授權後 **21 天內**可後台請款，逾期洽客服（p.101）。請款截止日會顯示在交易明細（p.54）。
- **信用卡請款僅接受全額**；**部分請款為申請制**（需另開通，p.50, p.101）。
- 請款狀態 enum（p.57）：`未請款 / 請款申請中 / 請款處理中 / 請款成功`。

## 6. 交易查詢與狀態機（客服 + 資料模型對照用）

### 6.1 查詢（p.46–48, p.54, p.57）
- 路徑：交易 > 交易查詢；快速查（交易日期 / 商店訂單編號）或精準查（支付方式、付款/請款狀態、卡號、授權碼、金額…）。
- **對接對照**：`商店訂單編號` = 我方 `merchantOrderId`；`91APP Payments 交易編號(PTxxxx)` = API `tradeId`；退款單 `PRxxxx`。

### 6.2 狀態 enum（p.57，對映我方 order/settlement 狀態機時參考）
| 類別 | 值 |
|---|---|
| 交易狀態 | 待付款 / 付款成功 / 付款失敗 / 付款取消 / 請款成功 / 部分退款成功 / 全部退款成功 |
| 付款狀態 | 已付款 / 待付款 / 付款取消 / 逾時未付 |
| 請款狀態 | 未請款 / 請款申請中 / 請款處理中 / 請款成功 |

### 6.3 交易明細可見欄位（p.54）
基本資訊、付款資訊（卡號遮罩前6後4、發卡行、授權碼、**3D 交易**、收單機構、分期期數/每期金額）、交易歷程時間軸。

## 7. 設定 / 風控 / 通知信

### 7.1 支付方式管理（p.24–25；商店 > 支付方式管理）
- 逐一啟用/停用；**停用後該商店 API 交易即無法使用此支付方式**（會直接影響線上串接）。
- 各方式需個別申請 + 審核：LINE Pay 審核 **4–5 週**（p.28）、Apple Pay 約 3 工作天（p.34）、大哥付你分期 1–2 工作天（p.37）。
- **牌價 vs 議價**：手冊 p.24 顯示的是**標準牌價**（信用卡一次 2.8%、ATM 1%、超商 NT$28/筆、LINE Pay 0.2%…）；我方**報價單為專案議價**（信用卡 2.35%、ATM 0.9% 上限 20 元、超商 27 元/筆…，見評估文件 §8.5）。以報價單/合約為準。
- ATM 虛擬帳號有效天數（上限 60 天）、超商代碼有限時間（上限 168 小時）可調（p.25）。

### 7.2 黑名單管理（p.39–42；僅商店層級）
- 可封鎖：信用卡卡號(Token) / IP / Email / 手機。用交易編號鎖定或手動新增；封鎖與解除皆留操作歷程。
- **⚠️ 風控盲點**：`cardToken` 交易**不傳入 IP**，故 **cardToken 續扣不支援 IP 黑名單**（p.41）——續扣場景的風控要靠卡號/Email 維度，不能靠 IP。
- 阻擋回應：API 回 `StoreEmailBlacklist` / `StoreIPBlacklist` 等 error code。

### 7.3 通知信管理（p.15–23, p.121；設定 > 通知信管理）
- 三類：客戶 / 商店 / 消費者通知信，可分別開關、編輯收件人。
- **消費者通知信 5 封**（2026/03/03）：交易結果、付款取消、退款申請、退款完成、綁定支付方式；可設「交易來源=所有交易 / 僅收款連結」，不要可關（p.17, p.121）。
- ⚠️ **與我方 email 系統重疊**：91APP 會直接寄消費者通知信。我方已有 Resend 交易信體系——需決定「哪些信由 91APP 發、哪些由我方發」，避免重複打擾用戶（onboarding/退款信可能雙寄）。

### 7.4 收款連結（Payment Link，p.81–97）
- 後台可建 hosted 收款連結（URL + QR），逐連結設金額/支付方式/**交易結果通知網址**/品牌化 LOGO。
- **可重複付款（不限/指定次數）**但那是「同連結多次手動付款」，**非自動續扣**，不能當訂閱引擎。
- 用途：對 SoundLite 可作為**臨時補收款 / 客服手動開單**工具（例：企業客戶匯款、補開發票），非主要訂閱路徑。

### 7.5 保留款 / 爭議款（chargeback，p.61, p.67–68, p.103）
- 保留款來源：退款處理中、提領中、**交易爭議(chargeback)**。爭議款會**凍結**款項直到「判決無需吊扣」才歸還可用額度。
- 路徑：帳務 > 保留款查詢（2025/01 新增）；狀態 enum：保留中 / 已歸還 / 不歸還 / 取消保留。
- ⚠️ 後台手冊**無 chargeback「通知/舉證」專門流程說明**——爭議款如何通知商店、如何提交交易憑證抗辯，需另問 91APP。

## 8. ⚠️ 後台確認不存在 / 手冊未涵蓋（需向 91APP 確認）

全本 125 頁掃描後，以下對 SoundLite 關鍵、但後台手冊**完全沒有對應畫面**：

1. **訂閱 / 定期定額 / 續扣排程管理**：後台無定期扣款、綁卡清單、token 管理、續扣排程 UI。支付類型枚舉只有「一次付清 / 分期 / 國外卡」，**無「定期定額」類型**。→ 佐證續扣純靠 API(`cardToken`) 驅動、排程由商戶自建（與技術評估一致）。
2. **卡號到期自動更新（Account Updater）**：後台無管理畫面。（報價單有此收費項目 → 服務存在，但**開通/監控方式未知**，列入 Tier 0 待問。）
3. **綁卡機制線索**（p.22）：「綁定支付方式通知（僅信用卡）」揭露綁卡走 **3D 驗證成功後 + 授權 NT$5 不實扣** 建立 token——但**沒有管理清單**，商戶端需自建 token 生命週期管理。
4. **API Key / sharedSecret 輪替、callbackUrl 設定、API 呼叫來源 IP 白名單**：後台手冊未見自助管理畫面。LINE Pay 的介接參數（Channel ID/Secret）甚至**驗證後不可自助修改，須寄客服**（p.32）→ 金鑰輪替可能非自助，是營運痛點，須確認。
5. **chargeback 通知 / 舉證流程**：只有保留款「結果」畫面，無爭議處理流程。

## 9. 對 SoundLite 設計的影響（落地清單）

| 領域 | 影響 | 待辦 |
|---|---|---|
| **財務/現金流** | 提領制 + T+N 撥款 + 錢停虛擬錢包 | 設自動提領（每日/週）、保留退款準備金、會計對帳改用 91APP 帳務日 |
| **對帳** | 無 API，靠後台 zip 匯出（存 3 天、T-1）、AP/DS 拆列 | 決定對帳方式：人工下載 or 問 91APP 有無報表/SFTP API；對帳程式處理 AP/DS 合併 |
| **退款** | 受退款額度限制、額度 0 擋退、進保留款 | dunning/退費流程加「額度耗盡隔日重試」；監控退款額度 |
| **請款** | 自動/手動須洽客服切換 | 導入時談定「自動請款」，否則續扣要多一步 capture |
| **續扣** | 後台無管理，純 API 自建 | 續扣排程器 + token 生命週期管理自建（技術評估 §5） |
| **email** | 91APP 會發消費者通知信 | 與 Resend 體系分工，避免重複寄送 |
| **風控** | cardToken 續扣不支援 IP 黑名單 | 續扣風控靠卡號/Email 維度 |
| **客服** | 後台可查單、手動退款、RBAC 分權 | 客服 SOP：查單用商店訂單編號、退款權限獨立群組 |
| **資安** | 強制 2FA、RBAC、綁卡走 3D | 正面；營運帳號管理納入 SOP |
